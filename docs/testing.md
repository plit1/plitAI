# 테스트 전략 및 결과

## 실행 방법
| 종류 | 명령 | 환경 |
|---|---|---|
| API 단위 + 통합(E2E) | `cd apps/api && pnpm test` | 실제 PostgreSQL `plit_test` (이름에 test 없으면 실행 거부) |
| 웹 타입체크·빌드 | `pnpm --filter @plit/web typecheck && pnpm --filter @plit/web build` | |
| 브라우저 E2E | `apps/web/e2e/run.sh [core-flow phase3-flow phase4-flow phase5-flow]` | 흐름마다 새 DB `plit_e2e_*` 생성, API 는 NODE_ENV=staging(관리자 MFA 강제) |
| CI | `.github/workflows/ci.yml` (postgres 서비스 컨테이너) | GitHub Actions 통과 (첫 실행에서 Prisma generate 누락 발견·수정) |

## 세션 4 실행 결과 (Phase 5)
- API: **27 suites / 179 tests 통과** (세션 3 대비 +36) — 만료 계산 5·만료 e2e 6, 저장소 9(S3 는 SDK 모의 객체), 증빙 열람 3, 정산 규칙 4·정산/대사 e2e 5, 토스 규칙 4
- 브라우저 `phase5-flow`: 주문 → successUrl 금액 위변조 거절 → 정상 승인·패스 → failUrl → 환불 → 만료 예정 안내 → 증빙 제출·관리자 열람(감사 로그) → 정산(테스트 제외/포함)·CSV 합계 **통과**
- 미검증: 토스 위젯 렌더·실결제(도메인 차단), 실제 S3 업로드
- 발견·수정 결함: (1) 토스 customerKey 규칙 위반(회원 ID 사용) (2) 정책 발행 시 일부 숫자 항목만 검증 (3) E2E 헬퍼 경합: `waitForURL('**/admin')` 이 `/login?next=/admin` 에도 즉시 일치 → OTP 로그인 요청이 중단되는 간헐 실패 → 경로명 비교로 수정
- 4개 흐름(core·phase3·phase4·phase5) 전체 재실행 **36단계 모두 통과**

## 세션 3 실행 결과 (Phase 4)
- API: **20 suites / 143 tests 통과** (세션 2 대비 +48) — QUICK TEST 6(+채점·출제 5), 전략 규칙 5, 코칭 규칙 6, 전략·코칭 e2e 7(가짜 Claude: 요청 형태·비용·숫자 검증·거절·오류·일일 한도), 커뮤니티 9, 채팅 가드 4, 스터디룸 socket.io 6(실제 소켓 연결)
- 브라우저 `phase4-flow`: QUICK TEST → 전략·코칭(키 없음 폴백) → 플릿런 403 → 실시간 채팅 A→B → 스터디룸 글 커뮤니티 노출 → 좋아요·댓글 → 신고 → 관리자(MFA) 숨김 → 관리자 문항·AI 사용량 → 모바일 **통과**
- 실제 Claude API 호출은 하지 않음 (키 없음). 요청 형태는 가짜 클라이언트로 검증
- 발견·수정 결함: (1) DTO optional 필드가 undefined 로 기존 값 덮어씀(ES2022 class fields) (2) 소켓 인증이 이벤트보다 늦게 끝나는 경합 (3) AI 일일 한도가 성공 호출을 세지 않음(Prisma `not` 의 NULL 제외) (4) 댓글 입력과 섹션의 접근성 이름 중복 (5) 키 없을 때 "남은 횟수 0" 오해 표시

## 세션 2 실행 결과 (Phase 3)
- API: **12 suites / 95 tests 통과** (세션 1 대비 +44) — MFA 5, OAuth·계정연결 7, 오픈런 6, 텍스트필터 11, 시험일정 7(+파서 3), TOTP 8
- TOTP: RFC 6238 부록 B 공식 테스트 벡터 5종 일치
- 브라우저: `run.sh` 로 core-flow(전 단계, 관리자 MFA 포함)·phase3-flow(9단계 + 모바일) **모두 통과**
- 발견·수정 결함: (1) 다른 용도 JWT 를 Bearer 로 보내면 500 → 401 (2) 동의 체크박스가 클릭 즉시 반영되지 않음 → 낙관적 갱신 (3) 기본 JSON 본문 100KB 제한으로 CSV 거절 → 1.1MB (4) E2E 실행기가 서버 파이프를 잡아 종료되지 않음 (5) 날짜 검증에서 없는 월 입력 시 예외 → 오류 행 처리
- 세션 1 문서의 "dev DB 리셋 후 E2E" 는 실제로는 리셋이 실행되지 않았음(Prisma 가 AI 실행 차단, 출력 미확인) — 세션 1 E2E 결과는 기존 데이터 위에서 통과한 것. 세션 2 부터 새 DB 방식으로 교정

## 테스트 중 발견·수정한 결함
1. 600분 초과 세션의 INVALID 처리가 트랜잭션 롤백으로 사라져 세션이 영구 RUNNING → 트랜잭션 밖에서 확정하도록 수정
2. 웹 `useApi` 첫 렌더에서 `loading=false·data=null` 구간 → `/my/points` 직접 진입 시 화면 오류 → 파생 로딩 상태로 수정
3. 테스트에서 레이트 리밋이 가입을 막음 → 한도를 런타임 평가로 바꾸고 레이트 리밋 전용 테스트 추가
