# 테스트 전략 및 결과

## 실행 방법
| 종류 | 명령 | 환경 |
|---|---|---|
| API 단위 + 통합(E2E) | `cd apps/api && pnpm test` | 실제 PostgreSQL `plit_test` (이름에 test 없으면 실행 거부) |
| 웹 타입체크·빌드 | `pnpm --filter @plit/web typecheck && pnpm --filter @plit/web build` | |
| 브라우저 핵심 흐름 | API(:4000)·WEB(:3000) 기동 후 `node apps/web/e2e/core-flow.mjs` | Playwright Chromium, dev DB |
| CI | `.github/workflows/ci.yml` (postgres 서비스 컨테이너) | **GitHub 에서 아직 실행된 적 없음** (push 권한 대기) |

## 2026-11-09 실행 결과 (이 세션에서 실제 실행)
- API: **5 suites / 51 tests 통과** (단위 8 + E2E 43), 타입체크 통과
- WEB: 타입체크 통과, `next build` 성공 (14 routes, 첫 로드 JS ≈ 102~110 kB)
- 브라우저 E2E `core-flow.mjs`: **전 단계 통과**
  1 가입·세션 유지·가입축하 3,500P → 2 검색·관심 저장 → 3 챌린지 상세 → 4~6 테스트 결제·패스 발급·PREMIUM 참여 → 8~9 공부 25분 기록·도전 지표 → 10 증빙 업로드·제출 → 11 관리자 승인 → 12~13 20,000P 반영(잔액 23,500P)·감사 로그 → 모바일(iPhone 13) 가로 넘침 없음
  - 시간 경과(공부 25분, 시험일 경과)는 psql 로 DB 시각을 조정해 재현

## 테스트 중 발견·수정한 결함
1. 600분 초과 세션의 INVALID 처리가 트랜잭션 롤백으로 사라져 세션이 영구 RUNNING → 트랜잭션 밖에서 확정하도록 수정
2. 웹 `useApi` 첫 렌더에서 `loading=false·data=null` 구간 → `/my/points` 직접 진입 시 화면 오류 → 파생 로딩 상태로 수정
3. 테스트에서 레이트 리밋이 가입을 막음 → 한도를 런타임 평가로 바꾸고 레이트 리밋 전용 테스트 추가
